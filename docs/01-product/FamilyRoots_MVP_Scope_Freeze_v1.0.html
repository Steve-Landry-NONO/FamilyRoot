⚠️ Arbitrages des Conflits

Les éléments ci-dessous présentaient des incohérences entre documents. Voici les décisions finales :

Élément Statut Final Priorité Source de Vérité Justification
Forgot Password V1.5 SHOULD Audit ✓ / PRD ✗ L'Audit plaçait Forgot Password en MVP, le PRD aussi. MAIS pour un MVP rapide, on peut gérer via email support. Reporté V1.5 pour réduire le scope auth initial.
Social Login (Google/Apple) V1.5 SHOULD Audit ✓ / PRD ✗ Le PRD listait Social Login en MVP (US-004). Décision : OAuth complexifie le MVP (config stores, tokens). Email/password suffit pour valider le produit. Reporté V1.5.
QR Code Invitation V1.5 COULD Audit ✗ / PRD ✓ Le PRD incluait QR code dans US-050. L'Audit ne le mentionnait pas explicitement. Décision : Code texte + partage WhatsApp/SMS suffisent. QR est nice-to-have → V1.5.
Multi-familles V1.5 SHOULD Audit ✓ / PRD ✗ Le PRD disait "lecture seule MVP". L'Audit disait V1.5. Décision : MVP = 1 famille par user. Multi-familles complet en V1.5. Simplifie modèle data et UI.
Calendrier V1.5 SHOULD Audit ✓ L'Audit et le User Flow plaçaient Calendrier en V1.5. Confirmé. Les anniversaires apparaissent dans Dashboard/Notifs, pas besoin d'un calendrier dédié pour MVP.
Fil d'activité V1.5 COULD Audit ✓ L'Audit plaçait le fil d'activité en V1.5. Confirmé. Le Dashboard affiche les événements à venir, pas besoin d'un feed temps réel pour MVP.
Web Public (Landing + Pricing) HORS SCOPE — Audit ✓ MVP = mobile-only. Le site marketing et la page pricing sont hors scope technique MVP mobile. Peuvent être faits en parallèle (marketing) mais pas dans le backlog dev.
Web App Connectée V2 COULD Audit ✓ L'Audit plaçait la Web App en V2. Confirmé. Focus mobile-first. Le backend GraphQL permettra d'ajouter un client web plus tard.
