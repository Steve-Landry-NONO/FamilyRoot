🔐 1. Décision Architecture Auth

⚠️ Problème identifié : Le PRD mentionne Supabase Auth + table User avec password_hash. Ces deux approches sont incompatibles. Il faut trancher.

Options analysées

Option Description Avantages Inconvénients
A — Supabase Auth Supabase gère email, password, confirmation, sessions. Table profiles liée à auth.users. ✓ Confirmation email native
✓ JWT + refresh tokens
✓ RLS avec auth.uid()
✓ Moins de code		 ✗ Dépendance Supabase
✗ Moins de contrôle
B — Auth Custom NestJS gère tout : bcrypt, JWT, confirmation email, reset. ✓ Contrôle total
✓ Portabilité		 ✗ Plus de code
✗ Sécurité à gérer
✗ Rate limiting manual

✅ DÉCISION : Option A — Supabase Auth

  • Supabase Auth est la source de vérité pour l'authentification
  • La table auth.users (gérée par Supabase) stocke email, password_hash, confirmed_at
  • Notre table User devient Profile : profil applicatif lié via auth_user_id
  • Pas de password_hash dans notre schéma — Supabase le gère
  • Confirmation email via Supabase (magic link ou OTP natif)
  • JWT fournis par Supabase, validés côté NestJS via @supabase/supabase-js

Implications techniques

Conséquences sur le modèle de données :
  • User → renommé Profile
  • Champ auth_user_id: UUID (FK vers auth.users.id)
  • Suppression de password_hash, email_verified
  • email dédupliqué depuis auth.users pour convenience (dénormalisation acceptable)

📌 1.5 Clarifications Patch v1.1

1.5.1 family.code vs invitation.code

Attribut family.code invitation.code
RôleIdentifiant public stableJeton d'accès temporaire
FormatFAM-XXXXXX (6 chars)INV-XXXXXXXXXXXX (12 chars)
ExpirationJamais7 jours par défaut
UsageIllimité (affichage)Usage unique
Sert à rejoindreNONOUI

✅ Règle métier

Pour rejoindre une famille, on utilise uniquement invitation.code, jamais family.code.
Le family.code sert à identifier la famille (affichage, partage info, recherche future V2).

1.5.2 Contrainte MVP : 1 famille par profil

⚠️ CONTRAINTE MVP
En MVP, un Profile ne peut avoir qu'UNE SEULE ligne dans user_family.

Implémentation :
  • createFamily et joinFamily vérifient COUNT(*) FROM user_family WHERE profile_id = $1
  • Si count > 0 → erreur ALREADY_IN_FAMILY
  • Flag produit FEATURE_MULTI_FAMILY = false en MVP

Le modèle UserFamily prépare le multi-familles V1.5, mais l'API le bloque en MVP.

⚡ 5. Flux Backend — Transactions & Règles d'Écriture

5.1 Inscription + Création Famille (Flux Admin Fondateur)

1
Supabase Auth : signUp()

Email + password → Supabase crée auth.users row + envoie email confirmation

supabase.auth.signUp({ email, password })
2
Trigger DB : on_auth_user_created

Supabase trigger crée automatiquement une row Profile liée

INSERT INTO profile (auth_user_id, email, first_name, last_name) VALUES (...)
3
User confirme email

Clic sur lien ou saisie OTP → auth.users.confirmed_at rempli

4
API : createFamily()

Transaction atomique :

BEGIN;
  INSERT INTO family (name, code, created_by) → family_id
  INSERT INTO user_family (profile_id, family_id, role='ADMIN')
  INSERT INTO member (family_id, linked_profile_id, first_name, last_name) → "Moi"
  INSERT INTO event (family_id, member_id, type='BIRTHDAY', event_date) si birth_date
COMMIT;

5.2 Rejoindre une Famille (Flux Invité)

1
API : validateInvitationCode(code)

Vérifie : code existe, non utilisé, non expiré

SELECT * FROM invitation WHERE code = $1 AND used_by IS NULL AND expires_at > NOW()
2
API : joinFamily()

Transaction atomique :

BEGIN;
  UPDATE invitation SET used_by = $profile_id, used_at = NOW()
  INSERT INTO user_family (profile_id, family_id, role='MEMBER')
  INSERT INTO member (family_id, linked_profile_id, ...) → "Moi"
  INSERT INTO notification (profile_id = admin, type='FAMILY_JOINED', ...)
COMMIT;

5.3 Ajouter un Membre à l'Arbre

1
API : addMember()

Vérification : user a accès à cette famille (via user_family)

2
Transaction BEGIN;
  INSERT INTO member (...) → new_member_id
  INSERT INTO relationship (member_id, related_member_id, type)
  IF type = 'SPOUSE' THEN INSERT relationship inverse
  IF birth_date THEN INSERT INTO event (type='BIRTHDAY', ...)
  INSERT INTO notification pour tous les user_family de cette famille
COMMIT;

5.4 Génération Notifications Anniversaire (CRON)

1
Job quotidien (Supabase Edge Function ou NestJS CRON) SELECT e.*, m.first_name, m.last_name, m.photo_url, f.id as family_id
FROM event e
JOIN member m ON e.member_id = m.id
JOIN family f ON e.family_id = f.id
WHERE e.type = 'BIRTHDAY'
  AND EXTRACT(MONTH FROM e.event_date) = EXTRACT(MONTH FROM CURRENT_DATE)
  AND EXTRACT(DAY FROM e.event_date) = EXTRACT(DAY FROM CURRENT_DATE + INTERVAL '7 days')
-- Répéter pour J-1, J
2
Pour chaque événement trouvé FOR EACH profile IN user_family WHERE family_id = event.family_id:
  INSERT INTO notification (profile_id, type='BIRTHDAY', title, content, metadata)
  CALL push_notification_service(profile.fcm_token, ...)

🔒 7. Row Level Security (RLS)

Supabase RLS permet de sécuriser les données au niveau PostgreSQL. Chaque table a des policies basées sur auth.uid(). 
-- Activer RLS sur toutes les tables
ALTER TABLE profile ENABLE ROW LEVEL SECURITY;
ALTER TABLE family ENABLE ROW LEVEL SECURITY;
ALTER TABLE user_family ENABLE ROW LEVEL SECURITY;
ALTER TABLE member ENABLE ROW LEVEL SECURITY;
-- etc.

-- Profile : user ne voit que son propre profil
CREATE POLICY "Users can view own profile" ON profile
    FOR SELECT USING (auth_user_id = auth.uid());

CREATE POLICY "Users can update own profile" ON profile
    FOR UPDATE USING (auth_user_id = auth.uid());

-- Family : user voit les familles dont il est membre
CREATE POLICY "Users can view their families" ON family
    FOR SELECT USING (
        id IN (
            SELECT family_id FROM user_family uf
            JOIN profile p ON uf.profile_id = p.id
            WHERE p.auth_user_id = auth.uid()
        )
    );

-- Member : user voit les membres de ses familles
CREATE POLICY "Users can view family members" ON member
    FOR SELECT USING (
        family_id IN (
            SELECT family_id FROM user_family uf
            JOIN profile p ON uf.profile_id = p.id
            WHERE p.auth_user_id = auth.uid()
        )
    );
