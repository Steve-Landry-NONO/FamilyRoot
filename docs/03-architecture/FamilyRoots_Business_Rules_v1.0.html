1. Authentification & Inscription

1.1 Inscription

AUTH-001
Champs obligatoires à l'inscription
L'inscription requiert : email (unique), mot de passe, prénom, nom.
AUTH-002
Validation email
Format email valide (RFC 5322). Unicité vérifiée côté Supabase Auth.
✅ steve@example.com
❌ steve@
❌ steve.example.com
AUTH-003
Validation mot de passe
Minimum 8 caractères. Au moins 1 majuscule, 1 minuscule, 1 chiffre.
✅ MonPass123
❌ password (pas de majuscule ni chiffre)
❌ PASS123 (pas de minuscule)
❌ Pass1 (< 8 caractères)
AUTH-004
Confirmation email obligatoire
L'utilisateur doit confirmer son email via OTP (6 chiffres) envoyé par Supabase. Sans confirmation, accès limité à l'écran de confirmation uniquement.
AUTH-005
Expiration OTP
Le code OTP expire après 60 minutes. Possibilité de renvoyer après 60 secondes.

1.2 Connexion

AUTH-010
Persistance de session
Le JWT est stocké en secure storage (Flutter). Refresh automatique avant expiration. Session valide 7 jours si inactif.
AUTH-011
Déconnexion
La déconnexion révoque le token côté Supabase et efface le secure storage local. Redirection vers l'écran de connexion.

1.3 Flux post-inscription

AUTH-020
Choix obligatoire : Créer ou Rejoindre
Après confirmation email, l'utilisateur DOIT choisir entre créer une famille ou rejoindre une existante. Pas d'accès au dashboard sans famille.
MVP Constraint: Un profil ne peut appartenir qu'à UNE seule famille. Cette contrainte est vérifiée dans createFamily et joinFamily.

2. Gestion des Familles

2.1 Création de famille

FAM-001
Champs obligatoires
Nom de famille (2-100 caractères), prénom du fondateur, nom du fondateur.
FAM-002
Génération du code famille
Format : FAM-XXXXXX (6 caractères alphanumériques majuscules). Généré automatiquement, unique, permanent.
FAM-[A-Z0-9]{6}
Exemple : FAM-7K3M9P
FAM-003
Rôle du créateur
Le créateur devient automatiquement ADMIN de la famille. Seul rôle avec permissions de suppression et gestion des invitations.
FAM-004
Membre "Moi" automatique
À la création, un Member est automatiquement créé avec linked_profile_id pointant vers le créateur. C'est le point d'ancrage dans l'arbre.
FAM-005
Tier par défaut
Toute nouvelle famille commence en tier FREE (15 membres max).
FAM-006 — Contrainte MVP : Si l'utilisateur a déjà une famille, createFamily retourne l'erreur ALREADY_IN_FAMILY.

2.2 Codes et identifiants

Type Format Usage Durée de vie
family.code FAM-XXXXXX Identifiant public (affichage, référence) Permanent
invitation.code INV-XXXXXXXXXXXX Jeton pour rejoindre une famille 7 jours (configurable)
Règle absolue : On ne rejoint JAMAIS une famille avec family.code. Seul invitation.code permet de rejoindre.

3. Système d'Invitation

3.1 Création d'invitation

INV-001
Génération du code invitation
Format : INV-XXXXXXXXXXXX (12 caractères alphanumériques). Unique, usage unique.
INV-[A-Z0-9]{12}
Exemple : INV-8HK3M9PQ2WXY
INV-002
Expiration par défaut
7 jours après création. Configurable de 1 à 30 jours.
INV-003
Qui peut créer une invitation
Tout membre de la famille (ADMIN ou MEMBER) peut créer des invitations.
INV-004
Traçabilité
Chaque invitation enregistre : créateur, date création, date expiration, utilisateur ayant utilisé le code, date d'utilisation.

3.2 Utilisation d'invitation

INV-010
Validation du code
Vérifications dans l'ordre : existe → non expiré → non utilisé.
Condition Erreur retournée HTTP
Code inexistant INVITATION_NOT_FOUND 404
Code expiré INVITATION_EXPIRED 410
Code déjà utilisé INVITATION_ALREADY_USED 409
User déjà dans une famille ALREADY_IN_FAMILY 409
INV-011
Effet de joinFamily
Transaction atomique : marquer invitation used → créer UserFamily (MEMBER) → créer Member "Moi" → notifier l'admin.

3.3 Partage d'invitation

INV-020
Méthodes de partage MVP
Copier le code texte, partager via apps natives (SMS, WhatsApp, etc.). Pas de QR code en MVP.
👤

4. Membres & Relations

4.1 Création de membre

MEM-001
Champs obligatoires
Prénom (2-50 caractères), nom (2-50 caractères), relation avec un membre existant.
MEM-002
Champs optionnels
Date de naissance, date de décès, genre, bio (max 500 caractères), lieu de naissance, photo.
MEM-003
Relation obligatoire
Tout nouveau membre DOIT être lié à un membre existant via une relation (PARENT, CHILD, SPOUSE).
MEM-004
Membre orphelin interdit
Impossible de créer un membre sans relation. Le premier membre (fondateur) est créé automatiquement.

4.2 Types de relations

Type Signification Relation inverse Stockage
PARENT A est parent de B B est CHILD de A 2 entrées créées
CHILD A est enfant de B B est PARENT de A 2 entrées créées
SPOUSE A est conjoint de B B est SPOUSE de A 2 entrées créées
SIBLING A et B sont frères/sœurs — Calculé dynamiquement
MEM-010
Relations bidirectionnelles
PARENT/CHILD et SPOUSE créent automatiquement la relation inverse. Une seule action utilisateur = 2 entrées en BDD.
MEM-011
Calcul des siblings
Les frères/sœurs sont calculés dynamiquement : membres ayant au moins un parent commun. Pas stocké en base.
siblings(A) = { M | ∃ P : isParent(P, A) ∧ isParent(P, M) ∧ M ≠ A }

4.3 Polygamie (support africain)

MEM-020
Conjoints multiples autorisés
Un membre peut avoir plusieurs relations SPOUSE. Pas de limite technique.
MEM-021
Enfants de différentes unions
Un enfant peut avoir un seul père biologique et une seule mère biologique (2 PARENT max). Les demi-frères/sœurs sont calculés via parent commun.

4.4 Validations dates

MEM-030
Contraintes sur les dates
• birthDate ≤ aujourd'hui
• deathDate ≤ aujourd'hui
• Si les deux : birthDate < deathDate
• Âge calculé : max 150 ans
MEM-031
Cohérence parent/enfant
Un parent doit avoir au moins 12 ans de plus que son enfant (si dates connues). Warning soft, pas bloquant.

5. Arbre Généalogique

5.1 Structure de l'arbre

TREE-001
Racines de l'arbre
Les "root members" sont les membres sans parents connus dans le système. Ils constituent le haut de l'arbre.
TREE-002
Générations
Calculées dynamiquement depuis les racines. Génération 0 = racines, +1 par niveau d'enfants.
generation(M) = max(generation(parent(M))) + 1
generation(root) = 0
TREE-003
Comptage générations
Affiché sur le dashboard : nombre de niveaux distincts dans l'arbre.

5.2 Affichage

TREE-010
Vue par défaut
L'arbre s'ouvre centré sur le membre "Moi" (linked_profile_id = current user).
TREE-011
Navigation
Zoom (pinch), pan (drag), tap sur membre = popup détails.
TREE-012
Indicateurs visuels
• Bordure spéciale pour "Moi"
• Icône si membre a un compte lié
• Grisé si décédé
• Photo ou initiales

5.3 Performances

TREE-020
Chargement optimisé
Query getFamilyTree utilise DataLoader pour éviter N+1 sur les relations. Tous les membres et relations chargés en une requête.
TREE-021
Limite d'affichage
Jusqu'à 100 membres affichés simultanément (tier FAMILLE). Au-delà, lazy loading par branche.

6. Notifications & Événements

6.1 Types de notifications

Type Déclencheur Destinataires Push
BIRTHDAY J-7, J-1, J (CRON) Tous les membres famille ✅
WEDDING J-7, J-1, J (CRON) Tous les membres famille ✅
MEMBER_ADDED Ajout d'un membre Tous les membres famille ✅
FAMILY_JOINED Nouveau membre rejoint Admin uniquement ✅

6.2 Événements anniversaire

NOTIF-001
Création automatique d'événement
Si birthDate est fourni à la création d'un membre, un Event BIRTHDAY est créé automatiquement.
NOTIF-002
Récurrence anniversaire
Les anniversaires sont récurrents chaque année. Le CRON compare le jour/mois de l'événement avec aujourd'hui.
isUpcoming(event, days) =
  dayOfYear(event.date) - dayOfYear(today) ∈ [0, days]
  // Gère le passage d'année
NOTIF-003
Rappels configurables
Par défaut : J-7, J-1, J. Stocké dans event.reminder_days (INT[]). Personnalisable en V1.5.

6.3 CRON quotidien

NOTIF-010
Exécution
Tous les jours à 08:00 UTC. Scanne tous les événements, génère les notifications pour les rappels du jour.
NOTIF-011
Dédoublonnage
Une notification n'est créée que si elle n'existe pas déjà pour ce (profile, event, reminder_day) dans les dernières 24h.

6.4 Push notifications

NOTIF-020
Service FCM
Firebase Cloud Messaging pour iOS et Android. Token FCM stocké sur le Profile.
NOTIF-021
Préférences utilisateur
Chaque utilisateur peut désactiver les push globalement ou par type. Stocké dans Profile.settings (JSONB).

7. Profils & Données

7.1 Données du profil

PROF-001
Synchronisation Profile ↔ Member
Si un Profile a un linkedMember, la modification de firstName/lastName sur le Profile met aussi à jour le Member, et vice-versa.
PROF-002
Avatar
Upload vers Supabase Storage. Formats acceptés : JPG, PNG, WebP. Taille max : 5 MB. Redimensionné à 256x256.

7.2 Données sensibles

PROF-010
Pas d'export MVP
L'export de données (GDPR) est prévu en V1.5. Les utilisateurs peuvent demander par email.
PROF-011
Suppression de compte
Hors MVP. En V1.5 : soft delete du Profile, conservation des Members (anonymisés si dernier admin).

8.2 Vérification des limites

TIER-001
Contrôle à l'ajout
Avant addMember, vérifier : COUNT(members WHERE family_id = X) < tier.maxMembers.
TIER-002
Erreur limite atteinte
Retourne MEMBER_LIMIT_REACHED (HTTP 402) avec message incitant à upgrader.
TIER-003
Downgrade
Si une famille downgrade et dépasse la nouvelle limite, les membres existants sont conservés mais aucun ajout possible.

8.3 Facturation (V1.5)

Hors MVP : Intégration Stripe prévue en V1.5. Pour le MVP, toutes les familles sont en tier FREE.
