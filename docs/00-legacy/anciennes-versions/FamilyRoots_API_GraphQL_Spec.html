1. Types GraphQL

1.1 Profile

# Profil applicatif de l'utilisateur connecté
type Profile {
  id: ID!
  email: String!
  firstName: String!
  lastName: String!
  fullName: String!          # Computed: firstName + lastName
  avatarUrl: String
  createdAt: DateTime!
  updatedAt: DateTime!
  
  # Relations
  family: Family              # MVP: 1 famille max
  linkedMember: Member        # Membre "Moi" dans l'arbre
  notifications(unreadOnly: Boolean): [Notification!]!
  unreadNotificationCount: Int!
}

1.2 Family

# Groupe familial
type Family {
  id: ID!
  name: String!
  code: String!               # FAM-XXXXXX (identifiant, PAS pour rejoindre)
  tier: FamilyTier!
  createdAt: DateTime!
  
  # Relations
  creator: Profile!
  members: [Member!]!
  memberCount: Int!
  generationCount: Int!       # Calculé depuis les relations
  upcomingEvents(days: Int = 30): [Event!]!
}

1.3 Member

# Membre de l'arbre généalogique
type Member {
  id: ID!
  firstName: String!
  lastName: String!
  fullName: String!
  birthDate: Date
  deathDate: Date
  isAlive: Boolean!           # Computed: deathDate == null
  age: Int                     # Computed si birthDate connu
  gender: Gender
  photoUrl: String
  bio: String
  birthPlace: String
  createdAt: DateTime!
  updatedAt: DateTime!
  
  # Relations
  family: Family!
  linkedProfile: Profile      # Si ce membre a un compte
  parents: [Member!]!
  children: [Member!]!
  spouses: [Member!]!
  siblings: [Member!]!         # Calculé: mêmes parents
  relationships: [Relationship!]!
}

1.4 Relationship

type Relationship {
  id: ID!
  type: RelationshipType!
  member: Member!
  relatedMember: Member!
  createdAt: DateTime!
}

1.5 Event

type Event {
  id: ID!
  type: EventType!
  eventDate: Date!
  reminderDays: [Int!]!        # Ex: [7, 1, 0] pour J-7, J-1, J
  daysUntil: Int!             # Computed: jours restants
  createdAt: DateTime!
  
  # Relations
  family: Family!
  member: Member               # Membre concerné (si applicable)
}

1.6 Invitation

type Invitation {
  id: ID!
  code: String!               # INV-XXXXXXXXXXXX (jeton pour rejoindre)
  expiresAt: DateTime!
  isExpired: Boolean!         # Computed
  isUsed: Boolean!            # Computed: usedBy != null
  createdAt: DateTime!
  
  # Relations
  family: Family!
  creator: Profile!
  usedBy: Profile
  usedAt: DateTime
}

1.7 Notification

type Notification {
  id: ID!
  type: NotificationType!
  title: String!
  content: String
  metadata: JSON              # { memberId, eventId, etc. }
  isRead: Boolean!            # Computed: readAt != null

4. Queries

me🔒 AUTH QUERY
Retourne le profil de l'utilisateur connecté avec sa famille (si existante).
query {
  me: Profile!
}

Retourne les données du dashboard pour la famille de l'utilisateur.

  dashboard: Dashboard!

Optimisation: Utilise DataLoader pour éviter le problème N+1 sur les relations membres → relationships → relatedMember.

Retourne le détail d'un membre spécifique.

  member(id: ID!): Member!

FORBIDDEN — Membre n'appartient pas à la famille de l'utilisateur

ParamTypeRequisDescription
codeString!OuiCode INV-XXXXXXXXXXXX

    after: String
    unreadOnly: Boolean = false
  ): NotificationConnection!

5. Mutations

5.1 Famille

createFamily🔒 AUTH MUTATION
Crée une nouvelle famille. L'utilisateur devient admin et un membre "Moi" est créé.
mutation {
  createFamily(input: CreateFamilyInput!): Family!
}

Transaction atomique

INSERT family (code = FAM-XXXXXX généré)
INSERT user_family (role = ADMIN)
INSERT member (linked_profile_id = current user)
INSERT event BIRTHDAY si birthDate fourni

Erreurs possibles

ALREADY_IN_FAMILY — MVP: l'utilisateur a déjà une famille
joinFamily🔒 AUTH MUTATION
Rejoint une famille via un code d'invitation valide.
mutation {
  joinFamily(
    invitationCode: String!
    firstName: String!
    lastName: String!
    birthDate: Date
    gender: Gender
  ): Family!
}

Transaction atomique

VALIDATE invitation (exists, not used, not expired)
CHECK user not already in family (MVP constraint)
UPDATE invitation (used_by, used_at)
INSERT user_family (role = MEMBER)
INSERT member (linked_profile_id = current user)
INSERT notification to admin (FAMILY_JOINED)

Erreurs possibles

INVITATION_NOT_FOUND — Code inexistant
INVITATION_EXPIRED — Code expiré
INVITATION_ALREADY_USED — Code déjà utilisé
ALREADY_IN_FAMILY — MVP: l'utilisateur a déjà une famille
createInvitation🔒 AUTH MUTATION
Crée un code d'invitation pour la famille (admin ou member peut inviter).
mutation {
  createInvitation(input: CreateInvitationInput): Invitation!
}
Génère un code INV-XXXXXXXXXXXX (12 chars alphanumériques). Expiration par défaut: 7 jours.

5.2 Membres

addMember🔒 AUTH MUTATION
Ajoute un nouveau membre à l'arbre avec une relation à un membre existant.
mutation {
  addMember(input: AddMemberInput!): Member!
}

Transaction atomique

CHECK relatedToMemberId appartient à la famille
CHECK tier limit (FREE: 15, FAMILLE: 100)
INSERT member
INSERT relationship (member → relatedMember)
IF SPOUSE: INSERT relationship inverse
IF birthDate: INSERT event BIRTHDAY
INSERT notification MEMBER_ADDED to all family users

Erreurs possibles

MEMBER_NOT_FOUND — relatedToMemberId inexistant
FORBIDDEN — Membre pas dans la famille de l'utilisateur
MEMBER_LIMIT_REACHED — Limite du tier atteinte
updateMember🔒 AUTH MUTATION
Met à jour les informations d'un membre.
mutation {
  updateMember(id: ID!, input: UpdateMemberInput!): Member!
}

5.3 Profil

updateProfile🔒 AUTH MUTATION
Met à jour le profil de l'utilisateur connecté.
mutation {
  updateProfile(input: UpdateProfileInput!): Profile!

Si l'utilisateur a un linkedMember, les champs firstName/lastName sont aussi mis à jour sur le membre.

7. Auth & Guards

7.1 Flow d'authentification

Supabase Auth gère l'authentification. Le client mobile/web obtient un JWT via Supabase SDK.
Le backend NestJS valide ce JWT et en extrait l'auth_user_id. 
# Header requis pour les endpoints 🔒 AUTH
Authorization: Bearer <supabase_jwt>

7.2 SupabaseAuthGuard (NestJS)

@Injectable()
export class SupabaseAuthGuard implements CanActivate {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = GqlExecutionContext.create(context).getContext().req;
    const token = extractTokenFromHeader(request);
    
    if (!token) throw new UnauthorizedException('UNAUTHENTICATED');
    
    // Valide le JWT via Supabase
    const { data: { user }, error } = await supabase.auth.getUser(token);
    
    if (error || !user) throw new UnauthorizedException('UNAUTHENTICATED');
    
    // Récupère le Profile applicatif
    const profile = await prisma.profile.findUnique({
      where: { authUserId: user.id }
    });
    
    request.user = profile;  // Injecté dans le contexte
    return true;
  }
}

7.3 Decorator @CurrentUser()

export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext): Profile => {
    const gqlContext = GqlExecutionContext.create(ctx);
    return gqlContext.getContext().req.user;
  }
);

// Usage dans un resolver
@Query(() => Profile)
@UseGuards(SupabaseAuthGuard)
async me(@CurrentUser() profile: Profile): Promise<Profile> {
  return profile;
}

7.4 FamilyMemberGuard

// Guard vérifiant que le user appartient à la famille concernée
@Injectable()
export class FamilyMemberGuard implements CanActivate {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const gqlContext = GqlExecutionContext.create(context);
    const { user } = gqlContext.getContext().req;
    const args = gqlContext.getArgs();
    
    // Vérifie l'appartenance à la famille
    const userFamily = await prisma.userFamily.findFirst({
      where: { profileId: user.id }
    });
    
    if (!userFamily) throw new ForbiddenException('NO_FAMILY');
    
    gqlContext.getContext().req.familyId = userFamily.familyId;
    return true;
  }
}

8. Résumé des Transactions

MutationTables modifiéesRollback si erreur
createFamily family, user_family, member, event Toutes les insertions annulées
joinFamily invitation (update), user_family, member, notification Invitation non marquée used, pas d'ajout
addMember member, relationship (1 ou 2), event, notification (N) Aucun membre créé, pas de notifs
Prisma $transaction: Toutes ces opérations utilisent prisma.$transaction() pour garantir l'atomicité.
